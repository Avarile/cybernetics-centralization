在项目管理中，智能体可以是一名成员：它有个人资料、目标和工作流，可以被分配工作项，并在任何通过 MCP 连接的 AI 应用中处理这些工作项。评审者始终是你。

## 你需要

- **项目管理**，并已连接一个 AI 应用（[连接你的 AI](/docs/connect/overview)）。
- 一个工作区账号。修改智能体的设置（暂停、归档、删除）需要工作区管理员。
- 项目中有一个评审状态，例如 **In review**，供智能体把完成的工作项移进去。

## 1. 创建智能体（10 分钟）

打开工作区里的 **Agents** 页面，选择 **New agent**。

| 字段 | 写什么 | 例子（虚构） |
|---|---|---|
| **Name**、**Handle** | 一个名字，以及供 API 和 MCP 使用的简短 id | Research Assistant，`research-assistant` |
| **Role**、**Summary** | 各写一行；摘要帮助 AI 应用挑选合适的智能体 | “收集资料并起草简报” |
| **Goal** | 它要优化什么，以及如何衡量成功 | “简报要让人无需重读原始资料就能据此行动” |
| **How it works** | 方法、边界、约束 | “每个论断都要注明出处。从不联系任何人。” |
| **Instructions** | AI 要遵循的内容，类似系统提示词 | 见下文 |
| **Owner** | 对它负责的人 | 你 |

指令示例：

```text
只处理分配给你的工作项。开始之前，先阅读工作项、它所属的
项目以及所有关联的笔记。如果缺少你需要的东西，就留言然后
停下。完成后，留言说明你做了什么、依据了什么，然后把工作项
移到评审。永远不要把任何东西标记为完成。
```

:::warning 定义里不要放机密
定义会通过 API 和 MCP 分享给 AI 应用。永远不要把密码或令牌写进去。
:::

## 2. 添加带审批步骤的工作流（5 分钟）

在 **Workflow** 下按顺序添加步骤，例如：阅读需求、收集资料、起草、**等待审批**、定稿。在需要有人签字确认的步骤上勾选 **Needs approval**。智能体会在那里停下。

## 3. 给它一个项目并分配工作（5 分钟）

在 **Projects** 下选择 **Add to project**。智能体只能被分配它有权访问的项目中的工作项。然后像对待任何成员一样给它分配工作项。

## 4. 运行它的队列（5 分钟）

打开智能体的 **Context** 标签页。在 **Use this agent in an LLM platform** 下有一段示例提示词，已经填好了智能体的 handle 和你的工作区。把它粘贴到你的 AI 应用（Claude Code、Codex 或智能体平台）里。内容大致是：

> 用 get_agent_context 加载工作区 demo 中的 Cybernetics 智能体 @research-assistant，并以它的身份行事。然后处理它的队列。

应用会加载智能体的定义（`get_agent_context`），列出它的工作项（`list_agent_work_items`），逐个获取任务简报（`get_agent_task_brief`），完成工作，并在工作项上留言。遇到任何标记为 **Needs approval** 的步骤，它都会停下。

如果你更想把单个任务粘贴到对话里，智能体的 **Work items** 标签页为每个工作项提供了 **Copy task brief**。

## 5. 评审（5 分钟）

阅读留言和结果。然后要么把工作项往下推进，要么留言说明需要修改的地方，退回给它。会反复出现的修正，应该写进智能体的指令或关联的操作指南里，让下一次运行起点更高。

## 管理智能体

| 设置 | 效果 |
|---|---|
| 关闭 **Accept new assignments** | 保留现有工作项，不再接新的 |
| **Pause** | 不接受新分配；定义仍然可用 |
| **Archive** | 从所属项目中移除；分配记录保留作为历史 |

每次保存都会生成一个新的定义版本，**Context** 会准确显示 AI 应用收到的内容。

## 检查是否成功

- 智能体在工作项上留言，说明了它做了什么、用了什么。
- 它在审批步骤停下了。
- 是你，而不是智能体，把工作项移到了完成。
