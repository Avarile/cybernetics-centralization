智能体是为一项工作而设的有名字的帮手：指令、模型、它可以使用的工具，以及处理较难部分的技能。这篇指南会打造一个虚构的“会议准备”智能体。换成你自己的重复性工作即可。

## 你需要

- 一个智能体平台账号，并已设置好 `cybernetics-data` 连接（[智能体平台](/docs/connect/agentic-platform)）。如果这项工作需要，再加上 `cybernetics-projects` 或 `cybernetics-crm`。

## 智能体的组成部分

| 部分 | 用途 |
|---|---|
| **Instructions** | 智能体是谁、如何行事，类似系统提示词 |
| **Model** | 平台提供的任何模型。以后可以更换，不影响其他任何东西 |
| **MCP Servers** | 它可以使用哪些连接，以及其中的哪些工具 |
| **Skills** | 完成一项工作的方法，用 Markdown 写成，需要时加载 |
| **Capabilities** | 内置能力，例如网页搜索、代码执行、文件搜索和记忆 |
| **Conversation starters** | 最多四个一键提示词 |

## 1. 先写技能（10 分钟）

技能承载的是“怎么做”，与智能体分开存放，这样多个智能体可以共用它，你也只需在一个地方改进它。选择 **Create skill**，填写三个字段：

| 字段 | 例子 |
|---|---|
| **Name** | `meeting-prep`（小写字母、数字和连字符） |
| **Description** | “当用户要求为与某个具体人员的会议或通话做准备时使用。”要写清楚什么时候适用：智能体正是据此决定是否加载它 |
| **Skill Content** | 下面的步骤，用 Markdown 写成 |

```text
1. 找到这个人（联系人或 CRM）。阅读最近的往来，以及双方
   做过的任何承诺。
2. 找到与他们关联的项目和任务，以及与这些项目和任务关联的笔记。
3. 写一份准备清单：已经决定了什么、还有什么悬而未决、双方各自
   承诺了什么、三个需要敲定的问题，以及要争取的结果。
4. 不超过 200 字。注明你用到的记录。
永远不要联系任何人。未经询问，永远不要修改记录。
```

打开 **Available to agent**，让智能体可以使用它。

## 2. 创建智能体（10 分钟）

打开 **Agent Builder**，填写：

- **Agent name：** 会议准备
- **Instructions：** “你使用用户自己的记录，帮助用户为会议做准备。回答之前先加载会议准备技能。如果缺少你需要的记录，就直说，而不是去猜。”
- **Model：** 这项工作用一个快速、便宜的模型就够了。
- **MCP Servers：** 选择 **Add MCP**，添加 `cybernetics-data`。只允许它查找和读取所需的工具：发现类工具（`list_bases`、`list_tables`、`get_table_schema`）以及 `query_records`、`get_record`、`get_record_neighbors`。如果你的客户在 CRM 里，再添加 `cybernetics-crm`，同样只开放查找和读取类工具。
- **Skills：** 选择 `meeting-prep`。
- **Conversation starters：** “帮我准备下一个会议”、“我答应过 <某人> 什么？”

## 3. 在一个真实的会议上试一试（10 分钟）

> 我 3 点半要和 Alex 见面，商量妈妈的生日。帮我准备一下。

把每一条事实都和它引用的记录核对一遍。哪里不对或含糊，就去改**技能**，而不是在聊天里纠正。

## 4. 随时更换模型（2 分钟）

因为你的数据在数据库里，方法在技能里，所以更换模型不会改变其他任何东西。要一次切换多个智能体，使用 Agent Hub 中的 **Change model**。

## 5. 可选：给它一个队列（10 分钟）

在项目管理里创建一个 handle 相同的智能体（例如 `meeting-prep`），这样就可以给它分配工作项，然后从这个智能体运行它的队列：[把工作分配给智能体](/guides/assign-work-to-an-agent)。

## 检查是否成功

- 智能体加载了技能，并引用了真实的记录。
- 它只拥有所需的工具：针对这项工作，只读。
- 在一次真实运行后，你改进过一次技能。
